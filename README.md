# Alaric Secure Browser

A cross-platform (Windows / macOS) exam-lockdown desktop application — equivalent to Pearson VUE / Respondus LockDown Browser — built with Electron.

---

## Features

| Category | What it does |
|---|---|
| **Kiosk fullscreen** | OS-level kiosk mode; no taskbar, no Alt-F4, no window borders |
| **Keyboard lockdown** | Blocks 40+ shortcuts (Win, Cmd, Alt-Tab, Ctrl-Alt-Del, F-keys, Dev Tools…) using `globalShortcut` + `uiohook-napi` |
| **Pre-exam checks** | Antivirus, firewall, display count, virtual machine, remote session, blacklisted processes & services |
| **Process monitor** | Scans every 3 s during exam; alerts proctor on TeamViewer, AnyDesk, VNC, OBS, Parsec, RustDesk, etc. |
| **Driver scan** | Scans every 30 s for VMware/VirtualBox kernel drivers (Windows) |
| **USB monitor** | Baseline at exam start; alerts on any new USB/HID device plugged in during exam |
| **Network lockdown** | Firewall rules allow only the exam server's IP + DNS; all other TCP blocked (WFP on Windows, pfctl on macOS); restored on quit |
| **Waiting room** | Camera preview (WebRTC), live chat with proctor, starts exam on proctor approval |
| **Live Monitor integration** | All violations forwarded to proctor's Live Monitor dashboard via WebSocket |
| **Machine ID** | Unique hardware fingerprint tied to each exam session |

## Quick Start (development)

```bash
# 1. Install dependencies
npm install

# 2. Generate the app icon (only needed once)
node scripts/gen-icon.js

# 3. Run in development mode
npm start
```

> **Note**: The project uses `env -u ELECTRON_RUN_AS_NODE` in the start script to prevent Claude Code's terminal environment from hijacking Electron. Safe to ignore.

## Usage

1. **Install** the DMG (macOS) or run the `.exe` installer (Windows).  
   Windows installer requires Administrator — the app must run elevated for keyboard hooks and firewall rules.

2. **Open** Alaric Secure Browser.

3. **Paste your exam URL** (e.g. `https://alaric-exam.onrender.com/exam/index.html?token=XXX`).  
   You can also use the deep-link format: `alaricexam://start?token=XXX&url=https://...`

4. **Pre-checks** run automatically:  
   - Displays, antivirus, firewall, blacklisted processes, VM detection, remote session, camera, microphone, internet connectivity.  
   - Resolve any ❌ items before proceeding.

5. **Waiting room**: Camera feed opens; the proctor can see your face and chat with you.  
   The exam starts only when the proctor clicks **Start Exam** in the Live Monitor.

6. **Exam** loads in full kiosk mode.  
   - Keyboard is locked; the exam page fills the screen.  
   - Security violations are logged live in the proctor's dashboard.

7. When the exam is submitted (or timed out), the app restores all firewall rules and closes.

## Deep Link Protocol

Register `alaricexam://` to launch the browser directly from an LMS or email link:

```
alaricexam://start?url=https%3A%2F%2Falaric-exam.onrender.com%2Fexam%2Findex.html%3Ftoken%3DXXXXXXXX
```

The protocol is registered automatically by the installer.

## Architecture

```
AlaricProctor/
├── main.js                    — Electron main process (window lifecycle, IPC, security orchestration)
├── preload.js                 — contextBridge API exposed as window.AlaricProctor
├── src/
│   ├── main/
│   │   ├── machineCheck.js    — Pre-exam system checks (AV, firewall, VM, processes…)
│   │   ├── keyboardLock.js    — Keyboard & shortcut blocking (globalShortcut + uiohook-napi)
│   │   ├── processMonitor.js  — Continuous process / driver scanning during exam
│   │   ├── usbMonitor.js      — USB device baseline + new-device detection
│   │   └── networkMonitor.js  — Firewall rules + connection scanning
│   └── renderer/
│       └── launcher.html      — Step-by-step launcher UI (URL entry → pre-checks → waiting room)
├── assets/
│   ├── icon.png               — App icon (generated by scripts/gen-icon.js)
│   └── entitlements.mac.plist — macOS entitlements (camera, mic, network)
├── scripts/
│   └── gen-icon.js            — Pure-Node icon generator (no external deps)
└── dist/                      — Build output (gitignored)
```

## Connecting to the Alaric Exam Server

The app talks to the same backend as the web exam:

- **WebSocket**: `wss://alaric-exam.onrender.com/ws` — waiting room protocol (`proctor_wait`, `proctor_joined`, `start_exam`, camera WebRTC)
- **Exam page**: loaded inside the kiosk window — standard web exam with Secure Browser extensions (`window.AlaricProctor` API)
- **Live Monitor**: `https://alaric-exam.onrender.com/admin/monitor.html` — proctor dashboard; shows waiting room candidates and live exam sessions

## Security Model

| Threat | Mitigation |
|---|---|
| Screen mirroring / remote control (TeamViewer, AnyDesk, RDP) | Process blacklist + SM_REMOTESESSION check + network firewall (server IP only) |
| Virtual machine | WMI manufacturer/model + driver scan |
| Injected keystrokes (rootkit via SendInput) | `LLKHF_INJECTED` flag detection *(V2 roadmap)* + WFP blocks exfiltration |
| New USB device (KVM, rubber ducky) | USB snapshot delta alert |
| Alt-Tab / Win key | `uiohook-napi` low-level hook intercepts OS-level keydown |
| Dev tools / right-click | `devTools: false` + `context-menu` suppressed |
| Physical second machine | Camera proctor verification |
